# 무당티 유통 대시보드

㈜운호컴퍼니가 유통하는 무(無)당티 젤리스틱의 제안 현황, 판매 기록, 누적 매출·이익, 로트별 재고·유통기한, 배송비를 한 화면에서 관리하는 내부용 페이지다.
Claude 아티팩트로 운영하며, 이 폴더는 그 페이지의 원본 소스를 보관한다.

> 운호 플랫폼 DB에 연결된 정식 버전은 독립 사이트 [`mudangtea/`](../../mudangtea/README.md)로 분리되었다. 아티팩트 버전은 별도 DB를 쓰므로 데이터가 서로 공유되지 않는다.

- 운영 페이지: https://claude.ai/artifact/8Lg7Gr8aYVBuKN3UfesYTi (비공개 — 소유자가 Share 메뉴로 공유한 사람만 열 수 있음)
- 원본: `index.html` (아티팩트 런타임 위에서 동작하는 단일 HTML)
- 공급가·판매가·거래처 정보는 소스에 없다. 모두 아티팩트 DB에 저장된다(이 저장소는 공개 저장소).

## 사용법

1. **설정** 탭에서 공급가(박스당, VAT 포함)·부가세율·권장 소비자가·건당 배송비·1건(카톤)당 박스 수를 확인한다. 소유자·편집자만 바꿀 수 있다.
2. **판매처·제안**에 제안할 곳을 추가하고 단계(발굴→제안→샘플→협상→입점→판매중, 보류·종료)와 다음 할 일·날짜를 적는다.
3. 입고되면 **재고·유통기한**에 로트(제조번호)·유통기한·입고 수량을 추가한다.
4. 출고·정산할 때마다 **판매 기록**에 날짜·판매처·로트·수량·판매가·배송비를 한 줄씩 남긴다. 누적 매출·이익·재고가 자동으로 바뀐다.
5. 샘플·반품 배송처럼 판매와 무관한 배송비는 **배송비** 탭의 '기타 배송비'로 남긴다.

## 계산 규칙

| 항목 | 규칙 |
|---|---|
| 매출 | 판매 수량(박스) × 판매가(박스당, VAT 별도) |
| 원가 | 판매 수량 × 공급가(VAT 별도). 공급가는 VAT 포함으로 입력하며, VAT 별도 = 입력값 ÷ (1 + 부가세율) |
| 판매 배송비 | 올림(수량 ÷ 1건당 박스 수) × 건당 배송비. 수량을 넣으면 자동으로 채워지고 직접 고칠 수 있다 |
| 배송비 합계 | 판매 기록의 배송비 + 기타 배송비(샘플·반품·재발송 등) |
| 이익 | 매출 − 원가 − 배송비 (매출·원가는 VAT 별도) |
| 이번 달 | 날짜가 이번 달(YYYY-MM)인 판매·기타 배송비만 |
| 재고 | 로트 입고 수량 − 그 로트로 기록한 판매 수량 (로트를 고르지 않은 판매는 재고에서 빠지지 않음) |
| 유통기한 | 오늘부터 남은 일수: 지남 / 90일 이내 임박 / 180일 이내 주의 / 그 이후 정상 |
| 다음 할 일 | 판매처의 할 일 날짜가 지났거나 7일 이내인 것 (종료 판매처 제외) |

## 데이터 구조

아티팩트 공유 DB. 문서마다 `updatedAt`, `updatedBy`(사용자 id), 새 문서는 `createdAt`, `createdBy`.

| 경로 | 필드 |
|---|---|
| `settings/main` | `supplyPrice`(VAT 포함), `vatRate`, `retailPrice`, `shipPerCarton`, `boxesPerCarton`, `note` |
| `accounts/<id>` | `name`, `channel`(공구·편의점·올리브영·약국·면세점·백화점·몰·라이브커머스·프랜차이즈·태국 수출·몽골 수출·중국(왕홍)·온라인·기타), `stage`, `dealType`(사입/위탁), `salePrice`, `contact`, `nextAction`, `nextDate`, `note` |
| `sales/<id>` | `date`, `accountId`, `lotId`, `qty`, `unitPrice`, `shipCost`, `note` |
| `lots/<id>` | `lotNo`, `receivedDate`, `expiry`, `qtyIn`, `note` |
| `shipments/<id>` | `date`, `kind`, `accountId`, `cost`, `note` |

## 권한

- 아티팩트 capability: `db`, `user`(profile)
- DB 규칙: `settings`는 모두 읽고 편집자(admin) 이상만 쓴다. 나머지는 기본값(참여자 interact 이상 쓰기, 보기 권한자는 읽기만).
- 판매 기록이 있는 판매처, 판매가 연결된 로트는 삭제할 수 없다(단계를 '종료'로 바꾼다).

## 수정 방법

`index.html`을 고친 뒤 같은 아티팩트 URL로 다시 게시한다. DB 데이터는 재게시해도 유지된다.
