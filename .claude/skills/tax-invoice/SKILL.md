# 매출 전자세금계산서 발행 준비

담당 에이전트: `accounting-clerk`(경리). 공통 규칙은 `.claude/company/common-rules.md`.

## 원칙
- 에이전트는 **발행 준비까지만** 한다. 홈택스 로그인, 공동인증서 비밀번호, 서명·발급 클릭은 사람이 한다.
- 공급자는 자사 법인 2곳만: ㈜운호컴퍼니(715-87-03094), 뷰티밤㈜(654-81-02686). SBJ컴퍼니·엣지라인의원 명의로는 발행하지 않는다.
- 금액은 계약서·발주서·견적서·사용자 지시에서만 가져온다. 근거가 없으면 비워 두고 사용자에게 묻는다.
- 면세 품목은 세금계산서가 아니라 (면세)계산서 대상이므로 따로 분리해 보고한다.

## 절차

1. **발행 대상 수집**
   - 사용자가 준 내용(거래처·품목·금액·공급일) 또는 앱 미수금 장부(`receivables`)·발주 자료에서 이번 발행 대상을 정리한다.
   - 거래처 사업자 정보(사업자번호·상호·대표자·주소·업태·종목·수신 이메일)는 `contacts`/`vendors` 데이터나 사업자등록증 사본에서 가져온다. 없으면 사용자에게 요청 목록을 만든다.

2. **입력 CSV 작성**
   ```bash
   python3 .claude/skills/tax-invoice/scripts/tax_invoice.py template projects/tax-invoice/2026-11/입력.csv
   ```
   한 줄 = 품목 1개. 작성일자는 공급시기(재화 인도일·용역 완료일, 월합계는 그 달 말일).

3. **검증 + 발행 대장 생성**
   ```bash
   python3 .claude/skills/tax-invoice/scripts/tax_invoice.py build projects/tax-invoice/2026-11/입력.csv projects/tax-invoice/2026-11/
   ```
   - 사업자번호 체크섬, 공급가액(수량×단가), 세액(과세 10% 원 단위 절사, 영세 0), 이메일, 필수 항목을 검사한다.
   - 발급기한(공급시기 다음 달 10일) 경과·임박을 경고한다.
   - 같은 공급자·작성일자·공급받는자·영수/청구 조합은 1장으로 묶고, 품목 4개 초과면 나눈다.
   - 종료 코드 1이면 오류가 있다는 뜻이다. 고칠 수 있는 것은 고치고, 정보가 없는 것은 사용자에게 묻는다.

4. **대표 보고**: `발행대장_요약.md` 내용을 그대로 보여 주고 "확인 필요" 항목을 짚는다.

5. **발급(사람)**: 홈택스 → 전자세금계산서 → 발급 → 건별(또는 일괄) 발급 화면에 대장 내용을 입력, 서명·발급.

6. **사후 기록**: 사용자가 알려 준 승인번호를 `발행대장.csv`에 기입하고, 미수금 장부의 청구일·청구액 반영안을 만든다(DB 직접 수정은 사용자 승인 후).

## 산출물 위치
`projects/tax-invoice/YYYY-MM/` — `입력.csv`, `발행대장.csv`, `발행대장_요약.md`. 거래처 개인정보가 들어 있으므로 외부 공유하지 않는다.
